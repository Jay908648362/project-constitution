# 启动 / 路由 / 蒸馏的写法要点

> v1.2.0 从主文件下沉。主文件只留**判据 + 指针**，细节在这里按需读。

---

## §1 启动：探测链怎么写

主文件给了探测链的模板，这里说**为什么这么写**，以及五个最容易写错的点。

### 分两类，别混

| 类型 | 例子 | 怎么写 |
|---|---|---|
| **项目内**的记忆 | `.workbuddy/memory/`、`docs/项目记忆.md` | **相对路径**——它躺在仓库里，换任何 agent 都能读到，不是某个工具专属 |
| **工具专属**的记忆 | `.claude/`、IDE 会话缓存 | 才需要**探测**——它可能不存在 |

混在一起的后果：把工具专属目录写成必读路径，换工具后第 0 步直接断。

### 五个写法要点

1. **探测顺序按"本机最常见"排**，每行一个候选，不解释为什么——agent 只需要能命中。
2. **必须写明"都没有怎么办"**：正确动作是**建一个**（`docs/项目记忆.md`），
   不是跳过、更不是停下来问。不写这句，agent 遇到空目录就卡住。
3. **命中即停，不重复创建**——已有可用载体就别再建第二份，双写必然漂移。
4. **降级路径要登记**：新建的载体要在 `AGENTS.md` §0 里登记路径，否则下次又找不到。
5. **探测链是示例不是清单**：换环境加一行即可，不要重写整个第 0 节。

## §2 路由：四条写法要求

主文件给了表格模板，这里是它的**写法要求**（决定这张表有没有用）。

1. **触发条件写场景，不写技能功能。**
   写「拿到别家板子的代码」，不写「硬件移植技能」——agent 靠场景匹配，不靠翻技能目录。
2. **标明「什么时候加载」**，尤其是「动手之前」这种时点。加载晚了等于没写。
3. **只放「本项目真的会用」的技能，不是「我装了什么」。**
   筛选标准是**这个项目的活会不会用到它**，不是它好不好用。
   装了二十个技能全塞进去，等于没有路由表——agent 分不清哪个才是当前该叫的。
   判断句式：「在这个项目里，遇到 X 场景，我会不会想叫它？」答否就删。
4. **远期才用的技能要标出来。** 第 4 阶段才碰得到的，注明「现在别加载」——
   否则 agent 在第 1 阶段就把它拉起来，白烧上下文还带方向。

### 三个反例

| 反例 | 为什么错 |
|---|---|
| 把 `~/.workbuddy/skills/` 全列一遍 | 那是技能清单，不是路由表 |
| 写「本机装了 idea-media-pipeline，可用于内容生产」 | 没说场景，也没说时点 |
| 写「内容创作相关技能」这种泛指 | 不是技能名，agent 无法调用 |

## §3 坑的归宿与蒸馏

### 三级载体，优先级从低到高

| 载体 | 性质 | 换工具后 |
|---|---|---|
| 工具记忆层 / 会话日志 | 过程，带日期带试错 | **可能读不到** |
| 项目自带的 `docs/项目记忆.md` | 半持久，项目内 | 一般能读到 |
| **`AGENTS.md` 的「已知坑」节** | **结论，跟着仓库走** | **永远在** |

**推论**：任何坑在写进记忆层的同时（或之后），都必须沉淀进 `AGENTS.md`「已知坑」。
记忆层是"随手记"，AGENTS.md 才是"上了保险的"。

### 蒸馏时机

```
记忆层里的日志（过程：带日期、带试错、带报错）
        ↓ 蒸馏
AGENTS.md「已知坑」（结论：现象 + 触发条件 + 怎么绕）
```

| 触发信号 | 动作 |
|---|---|
| 同一个坑出现**第二次** | 立刻蒸馏——说明它没被沉淀，才会重踩 |
| 阶段切换 | 把上一阶段的结论压进规范 |
| 日志超过 30 天没整理 | 清理并蒸馏，只留结论 |

蒸馏时**只留结论不留过程**：报错原文、试错轮次都可以砍，三段结论（现象 / 触发条件 / 怎么绕）一个都不能少。

> 这条纪律正是"通用性"的答案：**换工具会丢的是记忆层，不会丢的是仓库里的 AGENTS.md。**
> 真正让经验跨工具复利的动作，是定期把前者压进后者。
