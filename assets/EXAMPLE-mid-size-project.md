# 样例：一个中型项目立宪完的完整产出

> **这是"照做之后长什么样"，不是模板。** 模板在 `assets/*.template.md`，
> 这里展示的是**填完之后**的状态：结构密度、语气、以及每条为什么这么写。
> 虚构项目 `podkit`（播客一键出片工具，中型）只为示范，换成你的项目照样成立。
> 方括号 `【注】` 是讲解，真实产出里没有。

---

## 1. `docs/charter.md`

```md
# podkit · 目标与范围

## 目标
把一期播客从原始录音到可发布成片的时间压到 30 分钟内，且不需要剪辑经验。

## 范围
**做什么**
- 录音降噪 + 人声增强
- 自动生成带时间轴的字幕
- 导出竖版 / 横版两个成片

**不做什么**
- 不做多轨混音与配乐库
- 不做云端协作与多人编辑
- 不做移动端

## 约束
| 类型 | 内容 |
|---|---|
| 硬约束 | 全程本地处理，不上传原始录音 |
| 周期 | 6 周出第一个可用版本 |
| 资源 | 一个人，只有一台 16G 内存的机器 |
| 外部依赖 | whisper.cpp 的行为不受我们控制，只能适配 |

## 成功标准
- [ ] 一期 45 分钟录音，端到端 ≤30 分钟且无需人工干预
- [ ] 字幕时间轴准确率 ≥95%（抽 100 句人工核对）
- [ ] 换一台干净机器，按 README 能一次跑通
```

【注】「不做什么」三条都是**真会被塞进来的东西**——写空话（"不做无关功能"）等于没写。

## 2. `AGENTS.md`（中型完整版，约 60 行）

```md
# podkit · 协作约定

> 真相源在文件里，不在对话里。开工前读完本文件 + `CONTEXT.md`。

## 一句话定位
本地跑的播客一键出片工具：录音进，成片 + 字幕出。

## 0. 会话启动（进门前必做）

1. 读完本文件 + `CONTEXT.md`（术语以它为准，不出现第三套说法）。
2. 找记忆——按序探测，命中即读：
   1. `.workbuddy/memory/`：长期结论 + 最近一篇日志
   2. `docs/项目记忆.md`
   3. 都没有 → 新建 `docs/项目记忆.md`，并在本文件登记路径
3. 打开 `tasks/todo.md`，确认「进行中」是哪一条。
4. 读 `docs/进展.md` **顶部一条**——上一棒的交接。

> 铁律：不管走哪条路，坑必须落到本文件的「已知坑」。

## 1. 相关技能路由（干活前先看该叫谁）

| 遇到这件事 | 调用技能 | 什么时候加载 |
|---|---|---|
| 要生成/处理字幕时间轴 | `idea-media-pipeline` | **动手写字幕代码之前** |
| 抓在线资料被登录墙挡住 | `doc-fetch-login-wall` | WebFetch 返回空壳时立刻 |
| 要写新的 ADR | `documentation-and-adrs` | 三条件全中时 |

## 铁律

1. **不在 `tasks/todo.md` 上的新工作，先补进清单再动手。**
2. 绝不上传原始录音到任何外部服务。
3. 改任何音频参数前，先跑 `python tools/ab_test.py` 出对照，凭听感拍板不算数。

## 已知坑

| 现象 | 触发条件 | 怎么绕 |
|---|---|---|
| whisper 输出时间戳整体偏移 ~0.3s | 采样率不是 16kHz 时 | 送入前一律重采样到 16kHz |
| 导出竖版时音画不同步 | 帧率设为 30 而源是 29.97 | 导出前强制 `fps=29.97` |
| 内存爆掉 | 录音 >60 分钟且开了整段缓存 | 分块处理，块长 10 分钟 |

## 目录地图
- `src/` 源码 · `docs/` 文档与决策 · `docs/adr/` 决策记录
- `docs/进展.md` 交接日志（顶部即当前棒）· `tasks/` 任务与计划

## 常用命令
| 目的 | 命令 |
|---|---|
| 跑通全流程 | `python -m podkit run --in raw.wav` |
| 只重跑字幕 | `python -m podkit subs --in raw.wav` |
| 自检 | `python tools/check.py` |
```

【注】这份 AGENTS.md 为什么合格：
- §0 四步齐全，记忆层是**探测链**不是写死路径
- §1 路由表每个技能都写了**场景 + 时点**，不是"我装了什么"
- 已知坑每条都是**现象 + 触发条件 + 怎么绕**三段式，没有一句"注意内存"
- 命令都是真能跑的（对照 `src/` 与 `tools/` 核对过，不是抄 README）

## 3. `CONTEXT.md`（术语表节选）

```md
# podkit · 术语表

| 术语 | 含义 | 不这么说 |
|---|---|---|
| 原始轨 / raw | 未处理的录音文件 | 源文件、母带 |
| 成片 | 带字幕的最终视频 | 输出、结果 |
| 时间轴 | 字幕与音频对齐的时间戳序列 | 字幕轨、srt（srt 只是它的一種格式） |
| 块 / chunk | 分块处理时的最小单位（10 分钟） | 片段、分段 |
```

【注】只收**这个项目的特有词**，不收"API""缓存"这类通用词；也没有任何字段名 / 路径 / 默认值——那些属于 AGENTS.md 或代码。

## 4. `docs/adr/0001-音频处理全程本地.md`

```md
# 0001 · 音频处理全程本地

## Status
Accepted · 2026-09-02

## Context
最初考虑用云端 ASR，识别率更高且不占本机资源。但原始录音含未公开的访谈内容，
上传即违约；且用户机器只有 16G 内存，云端方案的网络往返也会成为瓶颈。

## Decision
音频处理（降噪、ASR、导出）**全部本地完成**，不引入任何需要上传音频的依赖。

## Alternatives Considered
- **云端 ASR API**：识别率高 ~5%，但要上传原始录音 —— 违约，直接排除
- **本地 GPU 加速**：速度快 3 倍，但要求 NVIDIA 独显，用户机器没有，且会锁死硬件要求
- **混合（本地降噪 + 云端 ASR）**：音频仍要出网，风险与全云端相同

## Consequences
- 处理速度受限于 CPU，45 分钟录音约 8 分钟 —— 可接受，仍在 30 分钟预算内
- 必须自己处理重采样（见「已知坑」里的时间戳偏移）
- 换模型时要重新做准确率基线
```

【注】四段齐全，Alternatives 三条都是**真考虑过的**并写了排除理由；
Date 是决策真实发生的日期。这不是"我们用了 PostgreSQL"那种废话。

## 5. `docs/进展.md`（顶部那条）

```md
## 2026-09-14 22:10 · 字幕模块跑通，卡在时间戳偏移

- 做了什么：接上 whisper.cpp，45 分钟录音能出完整 srt
- 为什么：字幕是成片的唯一阻塞项，先打通再优化
- 怎么理解：whisper 对**输入采样率**敏感，不是对模型大小敏感 —— 别去换模型
- 产出：`src/subs.py`、`docs/adr/0001-音频处理全程本地.md`
- 问题 → 解决：时间戳整体偏移 0.3s → 送入前统一重采样到 16kHz，已进「已知坑」
- 下一步：跑 `python tools/ab_test.py --cases cases/subs.json`，对照 100 句核对准确率是否 ≥95%
```

【注】「下一步」是**可直接执行的第一个动作**，不是"继续优化字幕"。
产出只给路径不重抄内容。「怎么理解」写的是判断依据，不是过程复述。
